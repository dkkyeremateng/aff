# Plan: Add selectable greeting styles to the `greet` CLI

Type: feature · Complexity: medium · Baseline: `7d919c920bb9172964c7bc8d5e90a199408c7480`

## Context

At pinned commit `7d919c920bb9172964c7bc8d5e90a199408c7480`, `cmd/greet/main.go` owns all command-line parsing in `run`: it accepts `--name`/`-n` and `--version`, reads a non-terminal stdin name only when no name flag was supplied, and always prints `greet.Hello(name)`. The `greet` package already exposes the seven required operations—`Hello`, `Farewell`, `Thanks`, `Welcome`, `Congrats`, `Salute`, and `Cheer`—with each function responsible for name normalization and its own empty-name text. This change must select among those existing functions from the command only; `greet/greet.go` and its package tests remain untouched.

The CLI uses a custom `flag.FlagSet`, suppresses its default output, and owns both usage and parse-error formatting. The new `--style` string flag must therefore be registered in that set, documented in `printUsage`, and validated explicitly after parsing. Keep the current behavior as the default: omitted `--style` selects `hello`; name flags continue to take precedence over piped stdin; and `--version` continues to exit before normal greeting dispatch.

## Phase 1: Specify style parsing and dispatch (TDD)

**Why:** The command must turn a constrained CLI value into exactly one existing package function without changing the package API or accidentally altering current name/stdin behavior.

**Test first** -> `cmd/greet/main_test.go`
- Extend the existing `TestRun` table with a success case for each canonical style value—`hello`, `farewell`, `thanks`, `welcome`, `congrats`, `salute`, and `cheer`—using `--name Ada` and asserting the exact corresponding output.
- Add a default-style regression case (no `--style`) that still returns `Hello, Ada!`, and a style-plus-stdin case proving the chosen style receives the trimmed piped name when no name flag is present.
- Add invalid-style cases (for example `--style wave` and `--style=wave`) asserting exit code 2, no stdout, an actionable stderr message naming the invalid value and the accepted values, and the existing `Run 'greet --help' for usage.` guidance.
- Retain/extend precedence coverage so `--version` with a valid `--style` remains version-only output and does not emit a greeting. Existing tests continue to cover name flags overriding stdin, including explicitly empty names.

**Modify** -> `cmd/greet/main.go`
- Register a string `--style` flag with default `hello` alongside the existing flags; no shorthand is requested.
- After successful parsing and the existing early version return, resolve the style through a local, explicit mapping from the seven lower-case CLI values to function values of the shared `func(string) string` shape. Invoke the selected function instead of the hard-coded `greet.Hello(name)`.
- Reject any value outside those seven canonical names before reading stdin or writing a greeting. Print the error through the existing `stderr` path and return 2, matching ordinary command-line validation failures; do not call or modify `unknownFlagName`, which is only for unrecognized flag names.
- Preserve `fs.Visit` name detection, stdin trimming/error handling, version precedence, output newline behavior, and the default `hello` result. Do not add aliases, case folding, or changes to functions in `greet/`.

## Acceptance Criteria

1. `greet --style hello|farewell|thanks|welcome|congrats|salute|cheer --name Ada` exits 0 and prints, respectively: `Hello, Ada!`, `Goodbye, Ada!`, `Thanks, Ada!`, `Welcome, Ada!`, `Congrats, Ada!`, `Respect, Ada!`, or `Nice work, Ada!`, each followed by one newline.
2. Omitting `--style` preserves the current `Hello` behavior, and a selected style uses the same trimmed piped stdin name when no name flag was supplied.
3. `--style` with a value outside the seven canonical lower-case choices exits 2, emits no greeting, identifies the bad style and allowed choices on stderr, and includes the existing help guidance.
4. Existing `--name`/`-n` precedence over stdin, empty name behavior, unknown-flag formatting, and `--version` early-exit behavior remain intact; version output wins over a valid style selection.
5. `greet --help` documents `--style` and its allowed values/default while retaining the manually aligned existing flag rows.
6. No file in `greet/` is modified.
